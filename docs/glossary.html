Course glossary

Exact terms used across modules. Sourced from CONTEXT.md and teaching vocabulary. Use these words consistently in artifacts and reviews.

Routing & intake

Route before grill
Before any grilling skill, write a one-sentence reason for the skill you will type. Foggy or multi-session work → /wayfinder. Scoped work with a codebase → /grill-with-docs. This is a routing decision, not the same as the /triage tracker skill.
/triage (tracker skill)
User-invoked skill that moves existing issues through the label state machine defined at setup. Use when issues need role movement in the tracker — not as a substitute for route-before-grill on new work.
Foggy / weak-context
Backlog item is underspecified, spans more than one session, or you cannot name the correct @ files yet. Route to /wayfinder first — do not force a single-session grill.
Properly primed
You attached the minimal correct @ files and folders before invoking a skill. The agent has the right code and docs in context — not an empty attach list, not a kitchen-sink dump.

Skills taxonomy

User-invoked skill
Typed by the human. Model invocation disabled. Orchestrators — e.g. /implement, /to-spec, /wayfinder.
Model-invoked skill
Reached by the agent or an orchestrator. Never a typed primary flow step — e.g. /code-review (auto from /implement), /tdd, /domain-modeling.
Three Pillars
Properties of the grilling engine: Context Engineering, Assumption Destruction, Stress Testing. Not exclusive to one skill.

Specification & tickets

Three-section spec
Output of /to-spec (synthesis only): acceptance criteria, non-goals, residual risks. Missing any section → reject.
Tracer-bullet ticket
Vertical slice delivering end-to-end observable behavior, with blocking edges declared. Sized for one focused agent session.
Slice test
Binary gate on every ticket: one-sentence user-observable behavior and recorded blockers. Fail either → re-slice immediately. (Reserve kill test for BML experiments.)
Group review
Room-level inspection of specs, tickets, or diffs. Peers or instructor reject incomplete sections or failing tickets on the spot — no partial credit.

Implementation & review

Red→Green only
TDD loop inside /implement: failing test at the seam, then minimal code to pass. Refactor is deferred to /code-review.
Refactor
Improving structure without changing behavior. In this course, refactor happens in /code-review — not inside the /implement loop.
CI (continuous integration)
Same automated checks your PR pipeline runs. Local verification must match those commands. “Agent said tests passed” is not done — pipeline green is done.
Dual-axis review
/code-review inspects two axes in parallel: Standards (repo conventions and code-quality patterns) and Spec (match to originating ticket). Must-fix findings get committed before you leave.
Pre-Build review
Separate agent review of ticket + plan before /implement. Record ≥2 concrete findings — surfaces gaps before code is written.
Must-fix
Review finding that blocks merge. Requires a committed diff before end of session — not a verbal promise.

Context & artifacts

Context
Everything the agent can see: rules, skills, @ files, chat history, tool results. Costs tokens; wrong amount produces confident fiction or diluted attention.
Issue tracker
Tool hosting repo issues (GitHub Issues, Linear, or local .scratch/ markdown). Skills such as /to-tickets, /to-spec, /triage read and write here.
Issue
Single tracked unit inside the issue tracker — bug, task, spec, or slice from /to-tickets.
Evidence artifact
Inspectable committed output proving a step occurred — e.g. CONTEXT.md entry, ADR stub, spec link, CI log. Chat recap alone does not count.

Prototype & BML

/prototype
Throwaway answer to one design question. Lives on a throwaway branch or folder; verdict captured; never merged to the default branch.
Kill test (BML only)
Binary pass/fail for Build-Measure-Learn experiments — not the same as the ticket slice test. See the BML course.
