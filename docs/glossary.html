Course glossary

Terms used on the learner pages. When a module introduces jargon, it either defines it in the same sentence or links here.

Routing and skills

Route before grill
Before any grilling skill, decide which typed skill fits: /wayfinder or /grill-with-docs. Write one sentence of reasoning. See Module 1. This is not the same as typing /triage.
/triage (tracker intake)
User-invoked skill for work already in the issue tracker: categorize, set state, verify, brief the agent. May grill inside triage. Use when the item is an existing issue/PR — not for the Day 1 “which grill skill?” routing gate.
User-invoked skill
You type it. Orchestrators: /wayfinder, /grill-with-docs, /to-spec, /to-tickets, /implement, etc.
Model-invoked skill
The agent reaches it — not a normal typed flow step. Example: you type /implement; the agent then runs /code-review.
Foggy
Cannot name the outcome in one sentence, or the work will take more than one agent session. → /wayfinder first.

Specs and tickets

Spec synthesis only
/to-spec writes the spec from the grill that already happened. It does not interview. Three mandatory sections: acceptance criteria, non-goals, residual risks.
Weak-context /to-spec
Ran /to-spec without @ attaching the files the decision depends on. Output looks polished and fails under implementation.
Properly primed
Correct @ files/folders attached before grill or spec synthesis.
Tracer-bullet ticket
Vertical slice with end-to-end observable behavior and declared blocking edges. Sized for one focused agent session.
Slice test
Ticket quality gate: one sentence of user-visible behavior + recorded blockers. Fail either → re-slice immediately. Formerly called “binary kill test.” Not the BML experiment kill criteria — see BML onboarding.

Implementation and review

Red→Green only
TDD loop inside /implement: add behavior at seams until tests pass. Refactor is deferred to /code-review.
Refactor
Cleanup that does not add the ticket’s user-visible behavior. Belongs in /code-review, not inside /implement.
CI (continuous integration)
The same checks the project runs on the pull request (e.g. the repo’s test/lint script). “Agent said tests passed” is not done — run that command locally; it must be green before implement is complete.
Dual-axis review
Post-implement closeout (auto from /implement): (1) Spec — does the diff match the ticket/spec; (2) Standards — is the code messy vs repo conventions.
Must-fix
Blocking review finding. Every must-fix gets a committed fix before the day ends.
Pre-Build agent review
After tickets and plan exist, before Build / /implement: run a separate review agent on ticket + plan; capture ~2 concrete findings (plan note or issue comment). Taught on Day 4; not a substitute for dual-axis closeout review.

Domain artifacts

ADR (architecture decision record)
Committed record of a domain or architecture decision. Stub is enough when the decision is new.
CONTEXT.md
Repo file for domain language and decisions. Grilling outcomes that matter must land here (or an ADR), not only in chat.
Three Pillars
Properties of the grilling engine: Context Engineering, Assumption Destruction, Stress Testing.
Group review
Instructor and peers read spec sections aloud. Missing any mandatory section → reject, return to grill, re-run /to-spec.
