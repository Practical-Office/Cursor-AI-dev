Debug, Review, Architecture, Prototype

Day 4

Goal

What this day is for

Give repeatable, model-invoked disciplines for cleaning AI-generated mess and settling design questions that cannot be answered on paper.

Teaching points

Must land

  • /diagnosing-bugs loop: reproduce → minimise → hypothesise → instrument → fix → regression-test. State the current hypothesis and next smallest experiment before changing code.
  • Dual-axis /code-review: Standards (repo conventions + explicit Fowler smells) ‖ Spec. Parallel sub-agents. Must-fix findings committed the same day.
  • /improve-codebase-architecture: visual HTML report, then the skill itself grills the selected opportunity. Reject large-rewrite proposals.
  • /prototype: throwaway code that answers one design question. Two exclusive branches (LOGIC terminal app / UI toggleable variants). Locate next to real code, mark as prototype, one command to run, no persistence by default, capture verdict on a throwaway branch, never harden into production.

Side-by-side

Practice gate: every must-fix finding from today’s reviews has a corresponding committed diff before 17:00. A review with zero fixes is a failed exercise.

Practice

Do the work

Run diagnosing loop on a real defect; produce dual-axis review with named Fowler smells; ship must-fix fixes; produce one prototype on the correct branch, remove from main tree, record verdict.

Success criteria

Binary checklist

Stop / Start

Behavior change

  • Stop leaving review findings unacted. Start requiring committed fixes before day close.
  • Stop settling “does this feel right?” during implement. Start routing them to /prototype.
