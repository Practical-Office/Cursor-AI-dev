Reality Check & Core Setup

Day 1

Goal

What this day is for

Make the cost of undisciplined AI usage visible. Install taxonomy. Drill route before grill until automatic.

Why for a new Dev

Most new Cursor users treat the agent as autocomplete. Accept → ship → discover mess later. Cost is rework hours and review cycles, not first-draft speed. This module makes the cost visible on a real ticket.

Hard truth

Grilling without all Three Pillars is theater. Chat explanation is allowed — credit requires a committed CONTEXT.md entry or ADR stub in your working repo (from Setup domain-doc layout). Verbal recap alone is not the deliverable.

Core concepts

Cursor surfaces

  • Chat = thinking / Q&A. Not the building surface.
  • Composer / Agent = multi-file building, terminal, primary surface for code changes.
  • Rules = always-on static context (short, specific, point at examples).
  • Skills = on-demand workflows; cost context only when invoked.

Skill taxonomy (architecture)

User-invoked (you type): ask-matt, grill-with-docs, wayfinder, triage, improve-codebase-architecture, setup-matt-pocock-skills, to-spec, to-tickets, implement

Model-invoked (agent reaches; not typed as normal flow step): prototype, diagnosing-bugs, research, tdd, domain-modeling, codebase-design, code-review, resolving-merge-conflicts

Worked example: You type /implement. The agent then runs /code-review. Typing /code-review as the main step is the wrong architecture. Same pattern: /grill-with-docs → /domain-modeling.

Route before grill

Decide which typed grilling skill fits before you grill. This gate is not the same as typing /triage — see the next block.

SituationTyped skill
Foggy / >1 session — cannot name the outcome in one sentence/wayfinder
Scoped + codebase/grill-with-docs
No codebase yetPrime, then /grill-with-docs once code exists

Never default every item into /grill-with-docs.

/triage = tracker intake

Use when work is already an issue or PR in the tracker: categorize, set state, verify, brief the agent. May grill inside triage. Day 1 pair practice on backlog items stays route → grill/wayfinder → committed CONTEXT/ADR unless the item is a real tracker issue.

Three Pillars

Properties of the grilling engine — not exclusive to one skill. One example question each:

  1. Context Engineering — attach the right @ files first. Example: “Which files must be attached before we decide the API shape?”
  2. Assumption Destruction — attack one unstated bet. Example: “What are we assuming about user permissions that we have not verified?”
  3. Stress Testing — failure at scale or removal. Example: “What breaks at 10× load, or if we remove this feature next quarter?”

Live demo (instructor)

  1. Real small backlog item.
  2. Path A: Agent, accept most suggestions, “ship”.
  3. Path B: weak grill (few questions, no pillars, no CONTEXT update).
  4. Path C: full three-pillar /grill-with-docs with correct @ priming.
  5. Side-by-side: questions, assumptions destroyed, residual risk, plan clarity, durable artifact?

Students state the difference in one sentence each.

Practice (pairs)

Two real backlog items each. Write one-sentence route decision (Wayfinder vs Grill). Run the correct user-invoked skill.

Deliverable (binary): committed CONTEXT.md entry or ADR stub per item in your repo. Chat recap does not count. No artifact → no credit.

Instructor enforcement

Kill pairs still “just chatting.” Force the artifact. If they cannot name the pillar used, the grill failed.

Success criteria

Stop / Start

  • Stop defaulting everything to /grill-with-docs. Start route before grill.
  • Stop treating chat-only recap as the deliverable. Start requiring a committed CONTEXT.md entry or ADR.
